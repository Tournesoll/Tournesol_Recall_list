# 贾源 UI 与非 AI 功能开发规范

## 1. 任务范围

负责：

1. 全站 UI 统一和移动端响应式修复。
2. 长文本横向溢出的系统性处理。
3. “题目解析/笔记”详细介绍区域及卡片级显示设置。
4. 最多 3 个未完成任务的背诵多任务功能。

不负责 MiMo 请求、AI 提示词、API Key、记录页 AI 分析或 Android 打包。

## 2. 页面整体概述与修改重点

### 全部页面

- 保留当前安静、工具型的视觉方向，统一间距、字号、按钮、弹窗、输入框和空状态。
- 最低以 360 px 手机宽度验收，不得出现页面级横向滚动。
- 长中文、连续英文、URL、JSON、Markdown、公式、知识库名称和题面必须可读。
- 底部导航、固定评分栏和软键盘不能遮挡内容。

### `/` 首页

- 修复摘要、图表、最近知识库和长标题在窄屏的布局。
- 保证四项底部导航在小屏中尺寸稳定。

### `/libraries` 与 `/libraries/:id`

- 分类树、操作按钮和长名称合理换行或省略，不挤出屏幕。
- 弹窗在手机端可滚动；危险操作清晰但不过度突出。
- 全部内容行在长题面下仍保留编辑/删除按钮。

### `/add`、`/add/manual`、`/add/format`、`/add/ai`

- 表单控件、分段按钮、文件/图片预览和 JSON 文本框适配手机。
- 手动添加将解析统一为“题目解析”，提供手动编辑。
- 为题目解析和笔记分别保存卡片级显示策略：关闭、答案后、始终显示。
- AI 页面只处理布局容器，不实现候舒扬的 AI 逻辑。

### `/study/tasks`（新增）

- 展示进行中和已完成两组任务。
- 进行中任务显示名称、范围摘要、进度、最近暂停时间，支持继续和删除。
- 最多 3 个未完成任务，达到上限时解释原因并禁用新建。
- 已完成任务显示结果摘要和完成时间，可保留历史；是否允许清理历史由实现说明明确。

### `/study/setup`

- 新建背诵时创建持久化任务，而不是只把队列放在路由 state。
- 支持自动任务名，并允许用户修改。
- 保持现有分类、知识库、类型、范围和手动选择能力。

### `/study`

- 将关闭操作改为“暂停任务”，暂停后保存并返回 `/study/tasks`。
- 每次评价后同步任务队列、会话状态和进度。
- 在题目下添加可折叠“详细介绍”区域；解析和笔记同时存在时使用标签切换。
- 为候舒扬的问 AI 组件预留明确插槽或接入位置，但不实现网络请求。

### `/study/complete`

- 完成时把任务标为已完成并保存完成时间和统计，不删除历史。
- 保留当前打卡能力。

### `/records`、`/mistakes`、`/settings`

- 完成响应式和长文本修复。
- 记录页为 AI 分析预留不破坏现有概览/日历的区域，但不写 AI 逻辑。
- 设置页保留笔记相关兼容设置；卡片级设置优先于旧全局默认值。

## 3. 允许修改的文件

```text

src/styles.css
```

发现依赖或共享 schema 需求时写入开发后说明，由项目负责人处理。

## 4. 多任务数据设计

在 `src/db.ts` 中新增 Dexie 版本，不能破坏 V1～V5 升级路径。建议表名为 `studyTasks`，模型至少包含：

```ts
type StudyTaskStatus = "active" | "paused" | "completed";

interface StudyTask {
  id: string;
  name: string;
  status: StudyTaskStatus;
  sourceSummary: string;
  itemIds: string[];
  queue: string[];
  session: Record<string, SessionState>;
  completedLogs: ReviewLog[];
  revealed: boolean;
  selectedOption?: number;
  createdAt: number;
  updatedAt: number;
  completedAt?: number;
}
```

可根据代码调整字段，但必须满足恢复和历史展示。注意：任务中的 `completedLogs` 是本轮状态快照；正式学习记录仍由 `reviewLogs` 表维护，不能重复写入。

旧 `recall-lite-study-resume-v1` 快照需要选择以下一种并记录：一次性迁移为任务，或检测后提示用户丢弃。不能让旧弹窗和新任务列表同时争夺恢复流程。

## 5. 多任务行为要求

- 创建任务前统计 `active/paused` 状态，达到 3 个时拒绝创建。
- 新任务创建后进入背诵，任务成为当前活动任务。
- 暂停必须先持久化当前卡片状态，再导航到任务列表。
- 继续任务时过滤已删除的 item id；队列为空则安全完成或提示无有效内容。
- 每次完成一张唯一卡片后更新任务进度。
- 完成本轮后保存完成状态、统计和完成时间，任务历史不占 3 个名额。
- 删除未完成任务需二次确认，只删除任务快照，不回滚此前已经产生的正式复习日志。
- 同一时刻不要出现两个“active”任务；切换任务时旧任务转为 paused。

## 6. 详细介绍实现要求

- 新数据统一使用 `explanation` 和“题目解析”语义；兼容读取旧 `explanationType`。
- 建议为卡片添加独立显示字段，例如 `explanationDisplay` 和 `noteDisplay`，取值均为 `off | after-answer | always`。
- 旧 `noteDisplay` 只有 `always | after-answer`，数据库/运行时需要提供兼容默认值。
- 手动编辑页允许分别选择解析和笔记的显示方式。
- 背诵页根据当前是否揭晓和两个显示策略决定整个区域及标签是否出现。
- 区域支持折叠；切换卡片时恢复到合理默认标签，不能展示上一张卡片的内容。
- 内容渲染预留统一 Markdown 组件；若依赖尚未由负责人安装，不要自己修改依赖文件。

## 7. UI 与长文本规范

- 全局设置 `min-width: 0` 到需要收缩的 flex/grid 子项。
- 普通文本使用适当的 `overflow-wrap: anywhere`/`word-break`；不要对所有内容粗暴隐藏。
- JSON、代码和公式区域可在自身容器内横向滚动，但不得带动整个页面。
- 图片使用稳定的最大宽高和 `object-fit: contain`。
- Grid 使用能在窄屏下降级的轨道，避免固定宽度总和超过视口。
- 按钮文字允许合理换行，但固定图标按钮保持稳定尺寸。
- 弹窗最大高度考虑地址栏、底部安全区和软键盘，正文区域可滚动。
- 不引入新的大型 UI 组件库，不重做产品为营销页，不用装饰性渐变或复杂动画。

## 8. 测试规范

- `npm run build`。
- 页面宽度：360×800、390×844、768×1024、1440×900。
- 给知识库名称、题面、答案、解析、笔记、URL 和连续英文分别准备超长脱敏文本，确认页面级 `scrollWidth <= clientWidth`。
- 验证空内容、仅解析、仅笔记、解析和笔记都有、二者都关闭，以及三种显示策略。
- 从 V5 数据升级后原内容、记录和设置仍存在。
- 创建 3 个未完成任务后限制生效；完成一个后可再建；删除任务需确认。
- 暂停后刷新/关闭页面再继续，队列、进度、答案状态和选项状态一致。
- 任务引用的内容或知识库被删除后仍可安全打开。
- 连续快速评价和双击暂停不得重复写日志或创建重复任务。

测试结束后删除临时任务、测试数据、调试样式、临时路由、截图脚本和模拟组件。

## 9. 开发后必须输出

填写 `开发后产出文档/贾源/开发后说明.md`，至少写明：

- UI 设计原则及关键响应式断点。
- 每个修改文件的用途。
- Dexie 新版本、表结构和旧数据兼容策略。
- 多任务状态流和路由变化。
- 详细介绍显示规则和旧字段兼容。
- 为 AI 组件预留的准确位置/props。
- 测试设备、尺寸、场景和结果。
- 已知问题及需要负责人接入的内容。
