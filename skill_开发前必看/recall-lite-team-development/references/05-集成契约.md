# 模块接口与合并契约

## 1. 冲突控制原则

当前 `src/App.tsx` 同时承担路由、页面和业务逻辑，是最高冲突风险文件。本轮采用以下规则：

- 贾源是并行开发阶段唯一允许修改 `App.tsx` 的成员。
- 候舒扬将 AI 能力写成独立组件和纯函数，不修改 `App.tsx`。
- 项目负责人在贾源分支合并后统一接入候舒扬组件。
- 杨桀浩不修改源代码。

`src/domain.ts` 与 `src/contracts.ts` 已由袁翊博预置为共享合同。候舒扬和贾源只能消费其中的类型；修改字段、重命名或移动文件前必须先在 Issue 中说明并等待袁翊博确认。

## 2. 候舒扬交付给负责人的接口

AI 模块应优先使用 props/callback，不直接依赖 `App.tsx` 的内部 state，也不直接写 Dexie：

- `AiKeySettings`：自行读写本机 AI 配置，不接触备份数据。
- `AiImportWorkspace`：返回经过最终校验的卡片数组，由父页面负责选择知识库和写库。
- `StudyAiQuestionPanel`：接收当前卡片快照和 `revealed`，内部完成单轮请求；卡片 id 变化时重置。
- `StudyAnalysisPanel`：接收脱敏聚合数据，不自行读取 `db`。
- `MarkdownContent`：作为解析、笔记和 AI 输出的统一安全渲染候选。

候舒扬必须在开发后说明中给出真实类型签名；本文件不替代最终实现签名。

## 3. 贾源交付给负责人的接口

- 新任务页面和任务读写方法应位于 `src/features/study-tasks/**`，即使当前由 `App.tsx` 接线，也要避免继续堆积全部逻辑。
- “详细介绍”组件应位于 `src/features/details/**`，接收解析、笔记、显示策略和揭晓状态。
- `/study` 为 AI 问答预留位置：答案和详细介绍之后、评分操作之前，且只有揭晓后可用。
- `/records` 为 AI 分析预留位置：筛选器之后、概览内容之内或之后，父页面能够生成 7/30 天聚合数据。
- `/settings` 为本地 AI Key 配置预留独立分组。

## 4. 数据库责任

- 贾源负责在分支中实现 `studyTasks` 表和升级逻辑。
- 项目负责人合并时审核版本号、索引、旧数据兼容和备份策略。
- 任务表是否进入 V3 备份由负责人最终决定并记录；不得悄悄改变 V2 备份语义。
- 候舒扬的三个 AI 场景均不新增数据库表。

## 5. Markdown 责任

- 负责人统一批准和安装依赖。
- 候舒扬提供 AI 输出所需渲染能力或接口。
- 贾源在详细介绍中复用同一个公共渲染器，不另写不兼容的 Markdown 解析。
- 若并行期间无法直接导入对方模块，先以 props 和占位容器完成，最终由负责人替换；不得复制两份实现。

## 6. 推荐合并顺序

1. 基线 commit。
2. 贾源 UI/详细介绍/多任务 PR。
3. 候舒扬 AI 新增文件 PR。
4. 负责人共享接线和依赖 PR。
5. 集成缺陷修复 PR。
6. 杨桀浩文档 PR。
7. Android 发布 commit/tag。

## 7. “修改了哪里”统一格式

每位开发者在 PR 和开发后说明中逐文件写：

```text
文件：src/features/ai/import/AiImportWorkspace.tsx
性质：新增 / 修改 / 删除
目的：一句话说明
主要变化：说明组件、函数、数据字段或样式
影响页面：/add/ai
外部接口：props、export、回调或 schema
兼容性：旧数据、旧页面和失败行为
负责人操作：无需处理 / 需要在某文件某位置接入
验证：执行过的命令和手工场景
```

禁止只写“优化代码”“修改 AI”“修复样式”等无法用于合并的描述。
